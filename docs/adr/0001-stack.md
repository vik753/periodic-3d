# ADR 0001 — Стек проекта

Статус: принято, 2026-10-10.

## Контекст

Заказчику нужен быстрый и лёгкий фронтенд с плавной 3D-анимацией. Бэкенд — на выбор
команды; заказчик ожидает Python. Заказчик — фронтенд-разработчик и изучает FastAPI и
PostgreSQL, поэтому стек должен быть эталонным для индустрии.

## Решение

- Фронтенд: React 19, TypeScript, Vite, three.js через React Three Fiber 9 и drei 10,
  zustand для состояния сцены, TanStack Query для данных, React Router 7, i18next,
  Tailwind CSS 4. Шрифты: Unbounded (символы элементов) и Golos Text (текст) — оба с
  кириллицей.
- Бэкенд: Python 3.12, FastAPI, SQLAlchemy 2 (async) + asyncpg, Alembic, PostgreSQL 17
  с pgvector. API только читает данные.
- Конвейер данных: Python 3.12, httpx, Typer, numpy, spglib (кристаллы), RDKit
  (молекулы без готового 3D). Pymatgen и polars не берём: при объёме ~28 тыс. записей
  их функции избыточны, а зависимости тяжёлые.
- Инструменты: uv, ruff, mypy, ESLint, Vitest, pytest, Playwright.

## Последствия

- Один язык (TypeScript) во фронтенде и один (Python) в данных и API.
- Тяжёлые научные библиотеки живут только в конвейере; образ API лёгкий.
- three.js закрепляем на одной минорной версии (~0.182): R3F, drei и postprocessing
  чувствительны к версии three.

## Альтернативы

- Готовый просмотрщик молекул (3Dmol.js, NGL): свой WebGL-контекст ломает единый
  полёт камеры между сценами. Оставляем для проверки данных.
- Babylon.js: сильный движок, но экосистема React-интеграции слабее, чем у R3F.
- Neo4j для связей: наши связи простые, PostgreSQL с GIN-индексом закрывает все запросы.
