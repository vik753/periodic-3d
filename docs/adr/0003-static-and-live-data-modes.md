# ADR 0003 — Два режима данных: статический снимок и живой API

Статус: принято, 2026-10-10.

## Контекст

План: конвейер собирает набор данных, PostgreSQL + FastAPI отдают его, CDN кэширует.
Для демо на GitHub Pages сервера нет. Химические данные меняются редко: только при
новой сборке набора.

## Решение

- Живой режим (прод): PostgreSQL + pgvector → FastAPI (только чтение) → CDN → браузер.
- Статический режим (демо и резерв): команда API `export-static` проходит по всем
  GET-эндпоинтам и сохраняет ответы как JSON-файлы. Фронтенд читает их с того же хоста.
- Ответы обоих режимов строит один и тот же код API (одни схемы Pydantic и запросы),
  поэтому форматы совпадают.
- Поиск и мультивыбор в статическом режиме считаются в браузере по компактному
  индексу соединений (загружается лениво).
- Фронтенд выбирает режим переменной `VITE_DATA_MODE=static|api`.

## Последствия

- Демо работает без сервера и бесплатно.
- Пути статических файлов повторяют пути API: `/data/<версия>/elements/Fe.json`
  ↔ `/api/v1/elements/Fe`.
- Нужен CI-шаг: поднять PostgreSQL, загрузить набор, выполнить экспорт.

## Альтернативы

- Только API: демо требует платного сервера с первого дня.
- Только статика: теряем учебную ценность бэкенда и гибкие запросы (похожесть, поиск).
