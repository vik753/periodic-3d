# ADR 0002 — Разработка через GitHub Actions

Статус: принято, 2026-10-10.

## Контекст

Облачная сессия разработчика (Claude) не имеет интернета, кроме GitHub. Реестры npm и
PyPI недоступны, источники данных тоже. Логи GitHub Actions из сессии прочитать
нельзя (хост логов закрыт), а git и API репозитория работают.

## Решение

- Установка пакетов, сборки, тесты, скриншоты и загрузка данных идут в GitHub Actions.
- Lock-файлы (package-lock.json, uv.lock) создаёт CI и коммитит обратно в main
  (`tools/ci/commit-back.sh`). Коммиты от GITHUB_TOKEN не запускают новые workflow,
  поэтому цикла нет.
- Каждый шаг CI пишет вывод в `out/logs/*.log` (`tools/ci/run.sh`). Отчёты, логи и
  скриншоты публикуются в ветку `ci-results` (`tools/ci/publish-results.sh`).
- Демо разворачивается на GitHub Pages из ветки `gh-pages` после зелёного CI.
- Локально в сессии работают только лёгкие проверки: синтаксис Python, YAML,
  юнит-проверки на установленных пакетах, tsx.

## Последствия

- Цикл «правка → результат» занимает 3–6 минут вместо секунд. Поэтому правки идут
  крупнее, а проверки в CI — подробнее (скриншоты, отчёт о размере бандла, логи).
- Репозиторий публичный: минуты GitHub Actions бесплатны.
- Заказчик видит прогресс по живому демо на GitHub Pages.

## Альтернативы

- Сборка на компьютере заказчика: зависит от того, включён ли компьютер, и нагружает его.
- Зеркала пакетов в обход политики сети: запрещено правилами среды.
