# ADR 0006 — Векторная модель элементов и соединений

Статус: принято, 2026-10-11.

## Контекст

Заказчик хотел «векторную модель химических элементов», чтобы показывать самые
близкие связи. План отнёс это к версии 1.1. Набор данных уже содержит ~27 тыс.
соединений — этого достаточно, чтобы построить модель без внешних сервисов.

## Решение

- Конвейер строит 16-мерные векторы (файл `vectors.json` в наборе данных).
- Элементы: матрица «элемент × элемент» — в скольких соединениях пара встречается
  вместе. Счётчики переводим в PPMI и сжимаем через SVD до 16 чисел.
- Соединения: среднее векторов их элементов с весами по доле атомов.
- База: колонки `vector(16)` (pgvector), индекс HNSW по косинусному расстоянию.
- API: в карточке элемента — `similar` (6 похожих элементов), в карточке соединения —
  `similar` (8 похожих соединений). Статический экспорт сохраняет те же ответы.

> **Теория: что такое эмбеддинг и почему PPMI + SVD.**
> Эмбеддинг — это список чисел (вектор), который описывает объект так, что похожие
> объекты получают близкие векторы. Правило дистрибутивной гипотезы: «объект
> определяют его соседи». У слов соседи — другие слова в тексте. У элементов — партнёры
> в соединениях: Na и K оба образуют соединения с Cl, O, S, поэтому их векторы близки.
>
> 1. **Счётчики.** C[i, j] — число соединений, где есть и элемент i, и элемент j.
> 2. **PPMI** (positive pointwise mutual information):
>    PMI = log( P(i, j) / (P(i) · P(j)) ). Это мера «встречаются чаще, чем случайно».
>    Отрицательные значения заменяем нулём (PPMI): «встречаются реже» — шумный сигнал.
>    PMI убирает перекос в пользу частых элементов (O и H есть почти везде).
> 3. **SVD** раскладывает матрицу 118 × 118 и оставляет 16 главных направлений.
>    Так шум уходит, а общие закономерности остаются. Это тот же приём, что лежит в
>    основе LSA и близок к word2vec (Levy, Goldberg, 2014).
> 4. **Косинусное сходство** сравнивает направления векторов: 1 — одинаковые,
>    0 — не связаны. pgvector считает косинусное расстояние оператором `<=>`.
> 5. **HNSW** — граф «ближайших соседей» внутри индекса. Он находит похожие векторы
>    за миллисекунды без перебора всех строк. Цена — приблизительный ответ; для
>    подсказок «похожие соединения» этого достаточно.

## Последствия

- Без внешних моделей и ключей: модель прозрачна и воспроизводима.
- Модель отражает «химическое поведение» (с кем элемент образует соединения), а не
  физические свойства. Для свойств позже можно добавить готовые эмбеддинги
  (например, ElementEmbeddings) рядом с этими.
- Для старых наборов без `vectors.json` разделы «похожие» просто не показываются.

## Альтернативы

- Векторы из свойств элементов (масса, электроотрицательность…): не учитывают
  химию соединений.
- Внешняя языковая модель для эмбеддингов: нужен ключ API и платные запросы.
